1. Products mapped by our NLP is saved to Redis with query as key, what if someone searched for `Amul Milk`? We'll have to hit our NLP once more to map products for this query but we had few mapped ones in the key milk already.

Solution I have in my mind: (You may add optimizations if necessary)
1. Save unmapped products to Redis with query as key
2. Save each mapped product to Redis with its key: productName:source and include all the mapped ones for its value. We'll do this for all the sources even if there are duplicates because we want consistency.
3. In our backend-go: when we do applyPendingMappings, we try to iterate all the products and find the mapped ones from Redis since we know source and product name. We map those if they are in our current array since we only want to map available products, Redis is just a memoizing thing that will help us find what products can be mapped together. And we remove the mapped ones from our original array so that we don't have duplicates in our final array.
4. To handle new unmapped products, we can iterate through Redis keys while saving the data and always append new mapped products for keys as some products might not be available on some locations, we don't want to lose them if we try to PUT the keys in Redis.
